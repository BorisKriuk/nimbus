01  /  PUT A REAL FACT IN IT

Type something you'd be annoyed to have paraphrased.

An invoice number. A dosage. A git SHA. It gets encoded, appended to an append-only log, and a 4-byte pointer goes into a fixed table. The text itself is never rewritten, summarised, or compressed.

Note the asymmetry. Writing costs one encoder pass and four bytes. There is no LLM call, no reranker, no summarisation step. The expensive model only appears at read time, and only after the exact rows are already in hand.

03  /  THE FAILURE, STATED PLAINLY

Past the ceiling, it doesn't degrade. It goes silent.

When a cluster's 128-slot ring fills, the oldest pointer is overwritten. The text is still on disk, permanently, but nothing points at it. It is unreachable. A query for it returns zero rows — not an approximation, not a confident guess.

Open bug, still in the repo. A cluster split resets the exemplar ring and truncates it, so 128 pointers become 64 and half the addresses die at once. The counter meant to prevent this — protects — reads 0 on every single run. It has never fired. Tap FORCE SPLIT above and watch a block go red.

And the meter won't warn you. Resident bytes stay flat while reachability collapses, because the byte count is a property of the table shape, not of how much you can still find. Flat RAM is the feature and the blind spot in one number.

The narrow claim that survives: under a fixed byte budget you cannot exceed, this returns exact text and reports absence instead of inventing. That is the entire pitch. Anything broader is not supported yet.
